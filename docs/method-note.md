# DwellingOS: one-page method note

**Purpose.** For a supplied apartment address and date, show which captured public rental-law rules may apply, which cannot be established, and which properties would be affected by a supplied change. This is a research aid, not legal advice or compliance certification.

**Sources and extraction.** The official 87-record manifest is audited. Fifty-four supplied texts are readable; 33 entries contain links only. Of those 33, 22 are secondary context, two have verified supplements, two now have official-city-source recoveries, six publisher pages need terms review, and one official regulation remains capture-blocked. The competition build emits 57 candidate rules. Each emitted rule has a source URL, retrieval date when available, a citation and a quotation copied from the source. Much of the baseline uses reviewed source-specific anchors, so it is not evidence of fully general extraction. A separate, document-independent intake can propose candidate clauses from a new text. A reviewer must confirm force, effective date, coverage, exceptions, penalty and citation before publication.

**Address decision.** Jurisdiction is determined from state and a legal-city mapping in the supplied sample. New portfolio records require legal-city evidence; postal city alone is marked unverified. The deterministic evaluator handles state/city scope, future, pending and failed law. Missing property facts yield `unknown` with a named fact; source text is never replaced by invented rules. A reviewed new-law coverage predicate can check units, construction year and other supplied facts. If that predicate is absent, coverage remains unknown.

**Evidence backlog.** In the 500-row challenge sample, 462 city mappings are provisional postal-city assumptions, 242 unit counts and 212 construction years are missing, and all 500 lack owner type and occupancy evidence. These are explicit data-enrichment tasks, not silently filled values.

**Change tests.** The five organizer cases T1–T5 are evaluated against the sample. On the current build they return 250, 90, 140, 110 and 0 candidate addresses respectively; NJ state/local conflict candidates are flagged. These are reproducible prototype results, not a claim that all addresses have legal coverage verified.

**Validation.** The pipeline checks source integrity, organizer rule-schema fields, quotation presence, 500 unique property IDs, jurisdiction boundaries, explicit date transitions, rate-window expiry, negative results, browser/Python evaluator parity, ZIP/state-prefix conflicts, and an independent unseen-document intake example. Forty-six automated tests and 20 source-anchored reference cases pass. A separate source-first holdout checks nine extraction cases and eleven address cases. All annotations are non-attorney and targeted; none is a complete expert-reviewed legal gold set or a proxy for the private scoring script. The 100% citation figure applies only to **emitted** rules and does not measure recall over every provision in the corpus.

**Scale.** The judges' website displays a 500-property snapshot. The same evaluator has an indexed SQLite import and on-demand portfolio path. A 20-million **synthetic** row benchmark imported in 133.488 seconds, selected 2 million city candidates in 3.185 seconds, and assessed those candidates against one rule in 25.927 seconds on this machine. That proves the path runs at target row count; production reliability, concurrent service, real-property freshness and verified geocoding remain future work. See `docs/scale-architecture.md`.
